# Мидгард: Аванпост — витрина App Gallery / RuStore (дизайн)

## 1. Обзор

Подготовка **материалов витрины** для публикации MVP в **Huawei App Gallery** и **RuStore**: иконки, скриншоты, русские тексты, чеклисты загрузки. Живые IAP SDK, подпись release и production cloud save — **вне скоупа**.

| Параметр | Решение |
|----------|---------|
| Сторы | App Gallery + RuStore (один набор ассетов, отдельные чеклисты) |
| Язык витрины | Только русский |
| Источник арта | Существующий пиксель-арт из `assets/images/` |
| Ориентация скриншотов | Landscape (как игра) |
| IAP / подпись | Не в этом проходе |

## 2. Цели успеха

1. В репозитории есть готовые файлы иконок и скриншотов нужных размеров.
2. Есть готовые RU-тексты (название, короткое/полное описание) для копипаста в консоли сторов.
3. Есть чеклисты публикации для App Gallery и RuStore без пробелов «что грузить».
4. В приложении отображается человекочитаемое имя **«Мидгард: Аванпост»** и подключена брендовая иконка (не дефолтный Flutter).

## 3. Структура артефактов

```
store/
  README.md                 # индекс: куда что грузить
  listing.ru.md             # тексты витрины (общие)
  checklist-appgallery.md
  checklist-rustore.md
  icons/
    ic_launcher_512.png     # master 512×512
    # densitiy exports живут также в android/.../mipmap-*
  screenshots/
    01_hub.png              # город / выбор класса
    02_run_archer.png
    03_run_mage.png
    04_run_paladin.png
    05_boss_chest.png       # босс и/или сундук
    06_progress.png         # прогресс / статы (опционально)
```

Приложение:

- `android:label` → `Мидгард: Аванпост`
- `android:icon` → сгенерированные mipmap из master-иконки
- при необходимости: `pubspec.yaml` `description` на RU one-liner

## 4. Иконка

### 4.1 Композиция

Собрать из существующего арта (не новый маркетинг-арт):

- Фон: фрагмент / тональность `hub/town_bg.png` или сплошной насыщенный пиксельный градиент в палитре хаба.
- Центр: один узнаваемый герой (предпочтительно лучник или паладин) из `heroes/*.png`, крупно, читаемо на 48dp.
- Без мелкого текста на иконке; без чужих логотипов.

Master: **512×512 PNG**, непрозрачный (без альфы по краю для сторов, где запрещён прозрачный фон — если нужен — с непрозрачным фоном).

### 4.2 Экспорты Android

Из master сгенерировать квадраты:

| Density | Size |
|---------|------|
| mdpi | 48 |
| hdpi | 72 |
| xhdpi | 96 |
| xxhdpi | 144 |
| xxxhdpi | 192 |

Положить в `midgard_outpost/android/app/src/main/res/mipmap-*/ic_launcher.png`.  
Исходник 512 — в `store/icons/ic_launcher_512.png` (+ можно оставить/обновить `assets/images/props/ic_launcher.png` как source в проекте).

## 5. Скриншоты

### 5.1 Формат

- **Ориентация:** landscape.
- **Рекомендуемый размер:** 1920×1080 (или 2340×1080 — допустимо, если оба стора принимают; baseline = **1920×1080**).
- **Формат:** PNG.
- **Количество:** минимум **4**, цель **5–6**.
- Не живой захват с устройства: **композиции** из тайлов/спрайтов игры (как коллажи art-wave), с короткими RU-подписями в пиксельном/чистом стиле **без** перегруза UI-хрома.

### 5.2 Набор кадров

| # | Файл | Содержание | Источники арта |
|---|------|------------|----------------|
| 01 | `01_hub.png` | Город Аванпост, выбор класса | `hub/town_bg`, `hub/icon_*` |
| 02 | `02_run_archer.png` | Забег лучника | `heroes/archer`, враги, фон биома |
| 03 | `03_run_mage.png` | Забег мага | `heroes/mage`, … |
| 04 | `04_run_paladin.png` | Забег паладина | `heroes/paladin`, … |
| 05 | `05_boss_chest.png` | Босс / сундук / дроп | `enemies/boss_ogre`, `props/chest` |
| 06 | `06_progress.png` | (опц.) статы Base/Job | UI-текст + иконки классов |

Каждый кадр: один визуальный фокус, одна короткая подпись (например «Выбери класс», «Беги и сражайся», «Улучшения забега»).

## 6. Тексты витрины (RU)

Файл `store/listing.ru.md`:

| Поле | Содержание (черновик для спеки; финальные строки — в файле) |
|------|---------------------------------------------------------------|
| Название | Мидгард: Аванпост |
| Короткое | Пиксельный side-scroller: город, забег, три класса, прокачка как в классическом фэнтези. |
| Полное | 2–4 абзаца: цикл город→забег→смерть→город; классы лучник/маг/паладин; Base/Job; временные улучшения; бесплатно + покупки (упоминание без деталей SDK). |
| Что нового (1.0.0) | Первый релиз MVP: город, забег, три класса, боссы и сундуки. |

Ключевые слова — короткий список в том же файле (без спама).  
Возрастной ориентир в чеклисте: **для всех / 0+** при отсутствии жестокого контента (пиксельный фэнтези-бой); финальный рейтинг — по форме стора.

## 7. Чеклисты сторов

### 7.1 Общее (оба)

- [ ] Иконка 512 + mipmap в APK
- [ ] ≥4 landscape-скриншота
- [ ] RU название / описание
- [ ] `versionName` / `versionCode` согласованы (`1.0.0+1` или актуальные)
- [ ] Privacy policy URL (заглушка-файл или внешняя ссылка — **обязательный пункт чеклиста**; если URL ещё нет — отметить блокер отдельно)
- [ ] Категория: Игры → Экшен / Аркада
- [ ] Контакт разработчика

### 7.2 App Gallery

Отдельный `checklist-appgallery.md`: аккаунт Huawei Developer, создание приложения, загрузка APK/AAB, возрастной рейтинг, privacy, скриншоты, описание, (IAP — «позже / не в MVP-витрине»).

### 7.3 RuStore

Отдельный `checklist-rustore.md`: кабинет RuStore, аналогичные поля, отличия по формату пакета/скриншотам если есть.

## 8. Изменения в приложении (минимальные)

1. `AndroidManifest` / `android:label` → человекочитаемое имя.
2. Замена дефолтных mipmap иконками из `store/icons`.
3. Опционально: строка названия в Flutter UI / `MaterialApp.title`, если сейчас техническое `midgard_outpost`.
4. Краткий раздел в `midgard_outpost/README.md` со ссылкой на `store/`.

Без подключения Huawei/RuStore SDK в этом проходе.

## 9. Вне скоупа

- Реальные IAP SDK и товары в консолях
- Signing configs / upload keystore в репо
- Production cloud save backend
- iOS / Google Play
- Живые скриншоты с эмулятора (композиции достаточны)
- Локализация кроме RU

## 10. Критерии приёмки

1. Каталог `store/` с текстами, чеклистами, иконкой 512, ≥4 скриншотами.
2. Android mipmap обновлены; ярлык приложения — «Мидгард: Аванпост».
3. README проекта указывает на `store/`.
4. Существующие `flutter test` не ломаются (витрина не трогает игровую логику).
