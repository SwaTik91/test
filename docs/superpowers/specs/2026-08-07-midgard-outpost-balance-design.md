# Мидгард: Аванпост — дизайн баланса (проход 1)

Связано с: `docs/superpowers/specs/2026-08-07-midgard-outpost-design.md`

## 1. Цель

Подогнать бой и прогресс под **средний** вкус сложности: смерть реальна на 2–4 минуте, босс — ощутимый чекпоинт, rogue-like апгрейды заметно влияют на выживаемость.

## 2. Подход

**Целевые метрики → константы** в `Balance`, `CombatMath`, каталоге мобов и XP-кривых + unit sanity-тесты. Без JSON data-layer и без полного автосимулятора забегов.

## 3. Целевые метрики (новый герой, без IAP, без run-upgrades)

| Метрика | Цель |
|---------|------|
| Первая реальная угроза | ~60–90 с |
| Типичная смерть | ~2–4 мин |
| Первый босс | `bossEveryDistancePx` ≈ 4000 px (~2–3 мин), убить можно с 1–2 апгрейдами |
| Интервал сундуков | ~900–1200 px |
| Дроп апгрейда с обычного моба | ~10–12% |
| Temp XP на оффер | порог ~80–100 |
| XP за забег ~3 мин до смерти | ≈ +1–2 Base level и +1–2 Job level |
| Золото за такой забег | ≈ 30–80 |

## 4. Параметры для изменения

### 4.1 `Balance`

Стартовые целевые значения (калибровка при реализации ±15%):

| Константа | Было | Цель |
|-----------|------|------|
| `monsterUpgradeDropChance` | 0.08 | **0.11** |
| `bossUpgradeDropChance` | 1.0 | 1.0 (без изменений) |
| `tempXpPerUpgrade` | 100 | **90** |
| `chestEveryDistancePx` | 1200 | **1000** |
| `bossEveryDistancePx` | 4000 | **4000** (оставить, подстроить скорость/HP босса) |

### 4.2 Бой игрока (`CombatMath`)

| Параметр | Направление |
|----------|-------------|
| `maxHp` база | слегка ↑, чтобы L1 переживал 2–3 удара гоблина (не 1) |
| basic attack damage | умеренно ↑ или скорость атаки, чтобы обычный моб умирал за ~1.5–2.5 с фокуса |
| зависимость от статов | сохранить RO-like (STR/DEX/INT/VIT), не ломать формулы классов |

Конкретные формулы фиксируются в реализации так, чтобы sanity-тесты проходили:

- L1 default stats: `maxHp ∈ [140, 200]`
- L1 archer/paladin basic damage (без крита-ожидания можно raw base): достаточно убить гоблина за ≤ 4 хита
- L1 mage magic basic: сопоставимо с физ (±20%)

### 4.3 Мобы / босс

| Роль | Цель |
|------|------|
| Обычный моб | урон игроку ~12–20% maxHp за удар; HP ≈ 3–4 удара L1 |
| Босс | HP ≈ 8–12× обычного; урон выше; гарантированный апгрейд (уже есть) |
| Спавн плотность | не душить L1 в первую минуту; нарастать с дистанцией |

### 4.4 Прогресс

| Параметр | Цель |
|----------|------|
| `xpToNextBase(level)` | чуть мягче на L1–5 (быстрее первые уровни), круче после |
| `xpToNextJob(level)` | аналогично |
| XP/золото с килла | подогнать под метрику «1–2 уровня за 3-мин забег» |
| Босс-награда | заметный пакет XP+золото (×3–5 обычного килла) |

Пример кривых (реализация может уточнить, тесты зафиксируют свойства):

```
xpToNextBase(level) = 15 + level * 12   // было 20 + level*15
xpToNextJob(level)  = 12 + level * 10   // было 15 + level*12
```

## 5. Sanity-тесты (обязательны)

1. L1 `maxHp` / basic damage в диапазонах §4.2  
2. Обычный моб: `playerHitsToKill ∈ [2, 5]`, `hitsToKillPlayer ∈ [5, 10]` при L1  
3. Drop chance и chest/boss intervals равны целевым константам Balance  
4. Симулированный пакет киллов (~N мобов) даёт Base/Job XP в коридоре «~1–2 level» через `ProgressService.applyRunRewards`  
5. Существующие тесты (boost multipliers, upgrade wiring) остаются зелёными

## 6. Вне скоупа прохода 1

- Перебаланс IAP цен и множителей бустов (кроме проверки, что бусты всё ещё заметны)
- Полный ребаланс каждого skill upgrade числами
- Автосимулятор Flame-забегов
- Изменение UX/контента умений

## 7. Критерий готовности

- Константы и формулы соответствуют таблице метрик  
- Sanity-тесты зелёные, полный `flutter test` зелёный  
- Краткий блок в README или спеке: «как крутить баланс» (где лежат константы)
